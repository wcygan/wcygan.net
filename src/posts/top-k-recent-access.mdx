## Problem

Add a top-k query to a key-value store. It returns the keys with the most successful reads in the rolling 24 hours before the query, along with their current values and access counts.

## Requirements

1. A successful read counts as one access.
2. Accesses older than 24 hours do not count toward the recent top-k results.
3. Return at most `k` entries, ordered by access count descending.
4. Break ties by key to make the order predictable.

</ProblemBoard>

## Operations

### Read a value

- **Input:** A key.
- **Result:** Its current value, or no value if the key does not exist.
- **Effect:** A successful read counts as one access.

### Find the most accessed keys

- **Input:** A maximum number of entries, `k`.
- **Result:** Up to `k` entries. Each contains a key, its current value, and its successful-read count in the rolling 24-hour window before the query.
- **Ordering:** Access count descending, then key order for ties.

## HTTP mapping

One possible HTTP mapping is:

```http
GET /keys/{key}
GET /top-k?k=3
```

A successful `GET /keys/{key}` returns the current value and counts as one access. For example:

```http
GET /keys/theme
```

```json
{
  "key": "theme",
  "value": "dark"
}
```

`GET /top-k?k=3` returns up to three entries, ordered by access count descending and then key order. For example:

```json
{
  "entries": [
    { "key": "theme", "value": "dark", "access_count": 18 },
    { "key": "language", "value": "en", "access_count": 12 },
    { "key": "timezone", "value": "UTC", "access_count": 7 }
  ]
}
```

## Progression

### 1. Single server without concurrency

You can build the ranking when `topK` runs, or update it as reads happen. Both approaches keep current string values and count only successful reads from the past 24 hours.

#### Batch ranking on each query

Build the ranking when `topK` runs.

- **Read:** Keep timestamps for each key. A successful `get` adds one and removes old timestamps for that key.
- **Query:** Remove old timestamps, scan stored keys, and sort those with recent reads.
- **Benefit:** Reads stay cheap, and there is little ranking state to maintain. This fits when `topK` runs rarely.
- **Tradeoff:** Every `topK` scans and sorts, even when it needs only a few keys.

```java
public final class KVStore {
    public record Entry(String key, String value, int accessCount) {}

    private static final Duration WINDOW = Duration.ofHours(24);

    private final Clock clock;
    private final Map<String, String> values = new HashMap<>();
    private final Map<String, Deque<Instant>> reads = new HashMap<>();

    public KVStore(Clock clock) {
        this.clock = Objects.requireNonNull(clock);
    }

    public void put(String key, String value) {
        values.put(key, Objects.requireNonNull(value));
    }

    public void delete(String key) {
        values.remove(key);
        reads.remove(key);
    }

    public Optional<String> get(String key) {
        String value = values.get(key);
        if (value == null) return Optional.empty();

        Instant now = clock.instant();
        Deque<Instant> times = reads.computeIfAbsent(key, ignored -> new ArrayDeque<>());
        prune(times, now.minus(WINDOW));
        times.addLast(now);
        return Optional.of(value);
    }

    public List<Entry> topK(int k) {
        if (k < 0) throw new IllegalArgumentException("k must be nonnegative");
        if (k == 0) return List.of();

        Instant cutoff = clock.instant().minus(WINDOW);
        List<Entry> result = new ArrayList<>();
        for (Map.Entry<String, String> item : values.entrySet()) {
            Deque<Instant> times = reads.get(item.getKey());
            if (times == null) continue;

            prune(times, cutoff);
            if (!times.isEmpty()) {
                result.add(new Entry(item.getKey(), item.getValue(), times.size()));
            }
        }

        result.sort(Comparator.<Entry>comparingInt(Entry::accessCount)
                .reversed().thenComparing(Entry::key));
        return List.copyOf(result.subList(0, Math.min(k, result.size())));
    }

    private static void prune(Deque<Instant> times, Instant cutoff) {
        while (!times.isEmpty() && times.peekFirst().isBefore(cutoff)) {
            times.removeFirst();
        }
    }
}
```

#### Incremental ranking on reads

Keep the ranking up to date as reads happen.

- **Read:** Keep accesses in one time-ordered deque. Each successful `get` updates the key's count and adds a ranking snapshot to a max-heap.
- **Query:** Expire old accesses, skip outdated heap entries, and take the highest-ranked current keys.
- **Benefit:** A small `topK` usually avoids scanning and sorting every key. This fits when small queries run often.
- **Tradeoff:** Reads do more work. Expiration or heap cleanup can still make one read or query slow.

```java
public final class KVStore {
    public record Entry(String key, String value, int accessCount) {}
    private record Access(String key, long generation, Instant time) {}
    private record Rank(String key, int count, long version) {}

    private static final Duration WINDOW = Duration.ofHours(24);

    private final Clock clock;
    private final Map<String, String> values = new HashMap<>();
    private final Map<String, Integer> counts = new HashMap<>();
    private final Map<String, Long> generations = new HashMap<>();
    private final Map<String, Long> versions = new HashMap<>();
    private final Deque<Access> accesses = new ArrayDeque<>();
    private final PriorityQueue<Rank> ranking = new PriorityQueue<>(
            Comparator.comparingInt(Rank::count).reversed().thenComparing(Rank::key));
    private long nextId;

    public KVStore(Clock clock) {
        this.clock = Objects.requireNonNull(clock);
    }

    public void put(String key, String value) {
        if (!values.containsKey(key)) generations.put(key, ++nextId);
        values.put(key, Objects.requireNonNull(value));
    }

    public void delete(String key) {
        values.remove(key);
        counts.remove(key);
        generations.remove(key);
        versions.remove(key);
    }

    public Optional<String> get(String key) {
        Instant now = clock.instant();
        expire(now);
        String value = values.get(key);
        if (value == null) return Optional.empty();

        accesses.addLast(new Access(key, generations.get(key), now));
        setCount(key, counts.getOrDefault(key, 0) + 1);
        compactRankingIfNeeded();
        return Optional.of(value);
    }

    public List<Entry> topK(int k) {
        if (k < 0) throw new IllegalArgumentException("k must be nonnegative");
        if (k == 0) return List.of();

        expire(clock.instant());
        compactRankingIfNeeded();
        List<Entry> result = new ArrayList<>();
        List<Rank> selected = new ArrayList<>();

        while (result.size() < k && !ranking.isEmpty()) {
            Rank rank = ranking.remove();
            if (!Objects.equals(versions.get(rank.key()), rank.version())) continue;

            selected.add(rank);
            result.add(new Entry(rank.key(), values.get(rank.key()), rank.count()));
        }

        ranking.addAll(selected);
        return List.copyOf(result);
    }

    private void expire(Instant now) {
        Instant cutoff = now.minus(WINDOW);
        while (!accesses.isEmpty() && accesses.peekFirst().time().isBefore(cutoff)) {
            Access access = accesses.removeFirst();
            if (!Objects.equals(generations.get(access.key()), access.generation())) continue;
            setCount(access.key(), counts.get(access.key()) - 1);
        }
    }

    private void setCount(String key, int count) {
        if (count == 0) {
            counts.remove(key);
            versions.remove(key);
        } else {
            counts.put(key, count);
            long version = ++nextId;
            versions.put(key, version);
            ranking.add(new Rank(key, count, version));
        }
    }

    private void compactRankingIfNeeded() {
        if (ranking.size() <= Math.max(32, 4 * counts.size())) return;

        ranking.clear();
        for (Map.Entry<String, Integer> item : counts.entrySet()) {
            ranking.add(new Rank(item.getKey(), item.getValue(), versions.get(item.getKey())));
        }
    }
}
```

#### Recommendation

Use **batch ranking** for a small store or when `topK` runs only occasionally. It keeps each read cheap and avoids maintaining a heap.

- **Batch fits:** Many reads between queries, a modest number of keys, or requests for a large `k`. Paying for one scan and sort at query time is usually reasonable.
- **Incremental fits:** Frequent `topK` queries that ask for a small `k` compared with the number of ranked keys. Updating counts during reads can avoid scanning and sorting every key for each query.
- **Measure the slow calls:** Both approaches may remove many expired accesses in one call. The incremental version may also skip stale heap entries or rebuild its heap, so its worst-case `topK` can still be slow.
