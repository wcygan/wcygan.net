## Problem

Build a service for 100 numbered tickets. Clients can find available tickets and claim one.

## Requirements

1. Tickets are numbered `1` through `100`.
2. Clients can list available tickets.
3. A client can attempt to claim a ticket and receive `true` or `false`.
4. Tickets cannot be oversold: each ticket can be claimed by at most one client.

</ProblemBoard>

## Operations

### Find available tickets

- **Input:** None.
- **Result:** The IDs of tickets currently available.

### Claim a ticket

- **Input:** A ticket ID and client ID.
- **Result:** `true` if the ticket is claimed by the client; otherwise `false`.

## HTTP mapping

One possible HTTP mapping is:

```http
GET /tickets?status=unclaimed
POST /tickets/{ticketId}/claim
Content-Type: application/json

{
  "clientId": "client-42"
}
```

The search response can encode available IDs as:

```json
{
  "ticketIds": [3, 7, 12]
}
```

The claim endpoint returns `true` when the claim succeeds and `false` when it does not. For example:

```json
true
```
