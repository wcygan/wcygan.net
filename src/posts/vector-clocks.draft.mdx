Each node keeps a vector clock with three positions: [<ClockLetter index={0} />, <ClockLetter index={1} />, <ClockLetter index={2} />]. Each position
holds the highest logical timestamp that this node knows about for the
corresponding node. A logical timestamp counts events rather than seconds. The
three values together describe one node’s knowledge of progress across all three
nodes. Step through two independent client writes, then follow the messages from <ClockLetter index={0} /> → <ClockLetter index={1} /> → <ClockLetter index={2} />.

<VectorClockDemo />

In this demo, a client write, a message send, and a message receive each increase
the node’s own counter by 1. A’s counter reaches 2 because it handles one write
and sends one message. When a node sends a message, it includes its vector clock
after increasing its own counter.

When a node receives a message, it compares the incoming vector with its own and
keeps the larger value in each position. It then increases its own counter by 1
to count the receive event. For example, C merges its [0, 0, 1] with B’s incoming
[2, 2, 0] to get [2, 2, 1], then increases its own counter to produce [2, 2, 2].
Taking the larger value preserves the highest known logical timestamp for each
node. The numbers are event counts, not stored data. The dashed lines show
message paths.
