[Conflict-free replicated data types (CRDTs)](https://en.wikipedia.org/wiki/Conflict-free_replicated_data_type) let copies of shared data accept updates independently. Once every copy receives the same updates, they agree.

A grow-only counter, or [G-Counter](<https://en.wikipedia.org/wiki/Conflict-free_replicated_data_type#G-Counter_(Grow-only_Counter)>), is a simple example. Each node stores a vector with one position per node: <span className="gc-vector">[<NodeLetter index={0} />, <NodeLetter index={1} />]</span>.

Each node increments only its own position, and adding the entries gives the total. Nodes share their vectors; when one arrives, the receiver keeps the larger number in each position. Since those counts only grow, a G-Counter cannot decrement or remove an increment. Those operations need a different CRDT design, such as a PN-Counter.

## How the merge operation works

A and B each increment once, producing <VectorNotation value={[1, 0]} /> and <VectorNotation value={[0, 1]} />. The merge keeps the larger number in each position, so their combined state is <VectorNotation value={[1, 1]} />.

## Why delivery order does not matter

Each merge keeps the larger count in every position.

Duplicates do not change the result: merging <VectorNotation value={[1, 1]} /> with <VectorNotation value={[1, 0]} /> still gives <VectorNotation value={[1, 1]} />.
