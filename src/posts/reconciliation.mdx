If your data gets into a messy state, you can reconcile it.

The reconciliation pattern is:

1. Schedule a job on an interval (daily, hourly, etc).
2. Query trusted data to identify records in a bad state.
3. Publish repair events to a log.
4. Let a log processor apply each repair idempotently.

One way to apply this pattern is to have [Airflow](https://airflow.apache.org/) schedule a job that uses
[Trino](https://trino.io/) to identify the bad records from your data lake (e.g., [Ceph](https://ceph.io/en/) object storage with [Apache Iceberg](https://iceberg.apache.org/) tables), then publish repair events into [Kafka](https://kafka.apache.org/), and have an online processor like [Flink](https://flink.apache.org/) reconcile the datastore (e.g., [MySQL](https://www.mysql.com/)). Change data capture closes the loop: [Debezium](https://debezium.io/) streams the repaired rows from the datastore through Kafka, and an indexer writes them back into the lake.
